# Highlight Keeper 閱讀側邊欄設計

## 目標

讓讀者在不離開文章的情況下理解全文推進，也能查閱少量值得標記的專有名詞和關鍵段落。

目前自動畫重點的預設 Prompt 要求涵蓋每個分類，並建議至少標註 10～20 個片段；每段還可能有 40～80 字延伸和來源。這會讓標註數量與文字量都偏多。使用者希望標註集中在專有名詞或特別重要的段落，並以短補充說明其意思或作用。閱讀全文時則希望看到自然連貫、能說清楚「因為、所以、但是、因此」的論述脈絡。

## 設計決策

新增 Chrome 原生 Side Panel，提供一個貼著文章閱讀、可跨分頁保留的閱讀介面。側邊欄用四個分頁隔開不同資訊：

1. **脈絡**：以一段短文交代文章主線及論述如何推進。主線與脈絡不再分成兩塊重複內容。
2. **專有名詞**：列出少量文章中的關鍵名詞，使用白話解釋其一般意思，以及它在本文中的用法。
3. **重點標註**：列出值得回看的原文片段，以及一兩句說明它的核心資訊或在論述中的作用。
4. **我的筆記**：讓使用者為目前文章自由記錄想法、問題和待查事項。

一次只顯示一個分頁，避免把不同內容堆在同一個長頁面。已確認的靜態互動草圖在 [`sidebar-wireframe.html`](../../../sidebar-wireframe.html)。

## 架構

採用 Manifest V3 的 `chrome.sidePanel` API。擴充功能新增 `side_panel.default_path` 指向側邊欄頁面，並新增 `sidePanel` 權限。Popup 保留目前功能，另加「開啟閱讀側邊欄」入口；不改變使用者點擊擴充功能圖示時開啟 Popup 的既有行為。既有頁面浮動面板與其快捷鍵繼續保留。

側邊欄是擴充功能頁面，負責呈現內容與跟隨目前作用中的分頁。文章標題、正文文字、標註和原文定位仍由該頁的 content script 提供。側邊欄以 canonical URL（缺少時退回目前 URL）作為資料識別，切換分頁或文章時載入對應的筆記。

Chrome 官方文件指出，Side Panel API 需宣告 `sidePanel` 權限；`sidePanel.open()` 從 Chrome 116 起提供，且須由使用者操作觸發。本設計以 Popup 裡明確的按鈕開啟側邊欄，並將最低支援版本訂為 Chrome 116。[Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

## AI 內容與資料

按下「整理本頁」後，沿用現有 OpenAI、Gemini、ChatGPT 網頁複製／貼上流程及使用者已設定的 API Key、模型與語言。側邊欄不會在開啟或換頁時自動呼叫模型。一次生成三種內容，避免為每個分頁重複傳送全文。

### 脈絡

- 以 3～5 句短文說明文章主張、原因、做法、轉折和結論，最多 350 個中文字。
- 保留原文支持的因果與轉折，用自然語句串連；不強行套用每一種連接詞，也不補造原文沒有的關係。
- 將主線與論述流程合寫，不再另產一份重複摘要。
- 只依據擷取到的文章內容；若文章沒有交代關鍵因果或背景，不自行補齊，必要時指出資訊不足。

### 專有名詞

- 僅選擇理解本文論述真正需要的名詞。
- 每個名詞須能在原文中定位，並有一段不超過兩句的白話解釋，說明本文脈絡中的用法。
- 不為普通詞彙建立詞條；沒有值得解釋的名詞時顯示空狀態，不湊數。

### 重點標註

- 挑選原文中值得回看的關鍵段落，不追求全面覆蓋每個分類或段落。
- 每次生成目標 3～5 個片段，硬上限 7 個，名詞標註也計入上限。
- 所有原文片段必須是可在頁面中定位的連續原文。每則補充最多兩句，說明片段傳達的核心資訊、重要性或與前後論述的關係。
- 預設不要求外部來源、延伸閱讀或背景猜測，避免把短標註變回長篇解說。
- 保留使用者現有「預覽後套用」設定。已有標註不重複建立，也不覆蓋手動標註。

### Prompt 相容性與儲存

- AI 預設 Prompt 改成上述數量與長度限制；移除「每個分類都要找片段」和「至少 10～20 個」等現有要求。
- 若儲存的摘要或自動畫重點 Prompt 完全等於舊版內建預設，升級時分別換成新預設；保留使用者自訂的 Prompt。
- 逐段延伸改為可選能力，不再是每筆標註的預設輸出。若兩個 Prompt 都仍是舊版預設，舊 `deepResearch: true` 視為舊預設並關閉；只要使用者自訂過其中一個 Prompt，就保留該設定值。
- 閱讀整理使用具名的 `context`、`terms`、`highlights` 三組輸出，並由共同解析層供 API 直連與 ChatGPT 複製／貼上流程使用。
- 生成的脈絡文字沿用 `hkGeneratedNotes` 的本機資料，以現有頁面 key 索引，增加格式版本與 `context` 欄位。維持舊 `note` 欄位可讀，舊筆記可在脈絡分頁顯示。
- AI 標註沿用當頁標註儲存，新增可選 `kind: "term" | "passage"` 欄位。舊標註沒有 `kind` 時仍顯示在「重點標註」分頁。名詞解釋存為該筆 `kind: "term"` 標註的註解，避免建立重複的名詞資料來源。選出的名詞與段落不可互相重疊；既有標註不重複標記或覆蓋。
- 個人筆記存於獨立的 `hkPersonalNotes`，依頁面 key 索引，與 AI 摘要分開保存。AI 重新生成不得覆蓋個人筆記。
- 新增的 `context`、`kind`、個人筆記和格式版本需隨既有匯出、匯入、分享流程保存；舊資料匯入時不要求這些欄位。

## 介面與互動

- 側邊欄固定顯示目前頁面標題、四個分頁與「整理本頁／重新整理」操作。名詞與標註數量用獨立的小徽章呈現，不與分頁名稱直接連寫。
- 「我的筆記」提供可編輯多行文字欄位，按鍵輸入後自動儲存到本機，並顯示儲存狀態。內容依文章分開，AI 生成不會覆蓋，也不會預設送給 AI。
- 點擊名詞或標註項目時，定位並短暫提示原文位置；若原文已無法定位，仍顯示筆記並提示位置失效。
- 切換作用中瀏覽器分頁時，更新標題、分頁內容及目前頁面的標註。若該頁已生成筆記，先顯示本機保存內容，不自動重生。
- 沒有可用 API Key 且使用者選擇 ChatGPT 時，使用現有複製 Prompt／貼上回應流程；未設定 AI 時提供設定入口。
- 受限頁面、無法讀取的頁面或正文擷取失敗時，保留側邊欄並顯示清楚的原因與可用操作，不讓擴充功能頁面崩潰。
- 生成中、無可用名詞／標註、解析失敗、模型錯誤及無原文可定位時，分別顯示對應狀態與重試方式。

## 隱私

文章文字只在使用者按下生成後，依目前選定的 AI 服務送出。沿用既有 API Key 本機儲存及服務商直連流程。側邊欄不新增第三方服務、遙測或背景傳輸；生成結果留在 `chrome.storage.local`。

## 不在本次範圍

- 不移除既有 Popup、頁面浮動面板、AI 設定、搜尋或筆記管理器。
- 不自動替每個已開啟頁面生成摘要。
- 不新增外部網頁搜尋、引用驗證或雲端儲存。
- 不重做顏色、標籤與整體視覺設計系統。

## 驗收條件

1. 使用者可從 Popup 開啟原生 Chrome 側邊欄，閱讀文章時不離開目前分頁。
2. 側邊欄以「脈絡／專有名詞／重點標註／我的筆記」四個分頁呈現；一次只顯示一種內容，計數以獨立徽章顯示。
3. 脈絡摘要以不超過 350 個中文字、3～5 句呈現主線與推進；名詞與片段補充各自保持精簡。
4. 一次生成至多 7 個總標註，目標 3～5 個；結果經現有預覽設定確認後才寫入頁面。
5. 新增名詞和標註都可定位回原文；無法定位時仍保留說明文字。
6. 切換瀏覽器分頁時側邊欄顯示相符頁面資料；已保存摘要不會觸發額外 AI 呼叫。
7. 舊版摘要、標註與自訂 Prompt 可繼續讀取；升級不會把自訂 Prompt 換成新預設。
8. 新增欄位通過匯出、匯入和分享往返，舊格式資料仍可載入。
9. 個人筆記按文章分開自動儲存，不被 AI 生成覆蓋，也不會預設送給 AI；匯出、匯入與分享可保存此欄位。
10. 未設定 AI、受限頁面、正文擷取失敗、模型回應無法解析時，側邊欄顯示可理解的狀態。

## 規格自我檢查

- 範圍集中在閱讀側邊欄與預設 AI 輸出量，沒有加入外部搜尋或其他子系統。
- 「脈絡」與「主線」已合併；AI 內容與個人筆記分開顯示。
- AI 標註數量同時計算名詞與段落，避免不同分頁各自達上限而重新過量。
- 舊 `note` 和不帶 `kind` 的標註有明確相容方式；使用者自訂 Prompt 不在遷移範圍。
- 無待補項目或互相矛盾的要求。
