# Highlight Keeper 統一側邊欄規劃

## 目的

點擊擴充功能圖示後，在同一個側邊欄完成目前頁面的閱讀、標註、筆記與設定。跨頁批次管理保留在筆記總覽。功能搬移時沿用現有資料格式，避免資料遺失或產生第二份設定。

## 導覽與功能位置

側邊欄頂部顯示目前文章標題、網域與重新整理；下方固定提供「本頁」、「閱讀」、「筆記」、「設定」四個主要入口。窄螢幕維持可讀的文字標籤與鍵盤操作，不依賴只有圖示的按鈕。

| 位置 | 功能 |
| --- | --- |
| 本頁 | 本頁標註清單、定位原文、編輯或刪除標註、頁面標籤、失聯標註提示、本頁分享與匯出。 |
| 閱讀 | AI 整理入口、複製 Prompt、貼上及套用回覆、API 整理、脈絡、閱讀地圖、名詞解釋、重點整理與導讀。整理完成後收起操作區，優先顯示內容。 |
| 筆記 | 本頁個人筆記及自動儲存狀態；提供「管理所有筆記」入口。 |
| 設定 | 顯示語言與字級、標註色票及舊色重設、AI 服務與分類、GitHub 備份及同步設定、全部筆記匯出／匯入。分組收合，避免設定遮住閱讀。 |
| 筆記總覽 | 全部頁面搜尋、標籤與網域篩選、排序、批次管理、標籤整理、重複頁面整理、同步衝突處理。由側邊欄直接開啟。 |
| 網頁內 | 保留選取文字的快捷工具列、標註細節選單、翻譯、AI 預覽確認及導讀定位。移除常規使用時必須另外開啟的工具面板。 |

## 主要流程

- 點擊擴充功能圖示進入「本頁」，直接看到標註與文章狀態。切換分頁不清除未儲存文字；切換文章前保存筆記。
- 選取網頁文字可直接標註，側邊欄即時更新；點側邊欄標註可定位原文。無法定位時保留內容並顯示狀態。
- AI 整理只在「閱讀」操作，保留切換 AI 網站時的來源文章、回覆驗證及預覽確認。
- 設定從側邊欄直接操作，無須跳出網頁工具面板；不存在可讀文章時仍可使用全域設定、備份與筆記總覽。
- GitHub 同步狀態與錯誤在設定中顯示，衝突可直接進入筆記總覽處理；同步不覆蓋未解決的衝突。
- 快捷鍵保留功能：畫重點維持原樣，原有閱讀及工具快捷鍵改為開啟側邊欄對應區域。需先驗證 Chrome 事件與權限限制，無法安全切換時保留既有行為並清楚標示。

## 介面原則

- 主要畫面只顯示目前任務需要的操作；分享、危險操作與較少使用的設定放在相關位置。
- 空白、載入、無法讀取、同步失敗及衝突都要有明確狀態。不要重複顯示同一錯誤。
- 沿用簡潔淺色風格，支援深色模式、窄側欄、鍵盤與螢幕閱讀器。圖示輔助文字；動畫短暫且尊重減少動態效果設定。
- 參考 PulsoIcon 和 motion-prompt 的動態細節，依現有原生 HTML/CSS 技術實作，避免為少量圖示引入 React。

## 搬移與驗證

1. 整理側邊欄導覽及空白狀態，保留原有閱讀流程。
2. 將標註清單、定位、編輯和頁面標籤搬入「本頁」，驗證網頁與側欄雙向更新。
3. 將顯示、色票與 AI 設定搬入「設定」，沿用現有 storage keys 和驗證邏輯。
4. 將備份與同步操作搬入「設定」，保留筆記總覽的批次管理與衝突解決。使用受控資料驗證匯入、匯出、衝突與網路失敗。
5. 調整快捷鍵與舊面板入口，確認新介面涵蓋既有功能後才移除舊入口；更新文件。
6. 執行既有測試與新增的關鍵流程測試，並在 Chrome 實際檢查不同寬度、語言、深色模式及不支援的頁面。

## SPA 網址與筆記歸屬

2026-11-13 使用者回報：從 `https://ai.kitmori.com/zh/daily` 切到 `/zh/article/gemini-4-carbon-is-now-available` 時，網址列已是文章，側邊欄仍顯示 daily，造成顯示錯頁筆記與標註失聯。網站使用 SPA 導航，頁面端呼叫的 history API 不保證能被隔離環境中的內容腳本攔截。換頁監聽以實際網址補充偵測，切換資料鍵並通知側邊欄；不合併不同文章路徑。`test/spa-navigation.js` 覆蓋這兩個網址、返回與追蹤參數；`test/duplicate-pages.js` 驗證不同路徑及內容衝突不會被合併。舊資料可能已存到錯誤鍵，不能未經核對自動搬移或覆蓋。網址正規化仍採用已辨識的內容參數白名單，尚未辨識的內容參數需另行評估，避免改動既有資料鍵。

同日再次回報切換頁面仍停在 daily。補查發現：內容腳本首次載入時若 canonical 仍是 daily，會錯誤採用這個鍵，且網址監聽把目前文章網址視為已觀察過，無法自行修正。資料鍵現改以網址列為準，測試涵蓋首次注入時 canonical 殘留前頁。舊資料不會自動改名或刪除。
